# MVP 기능 명세 및 검증 기준

## 사용자 흐름

로그인 → 통합 공고 검색 또는 URL 직접 등록 → 출처와 원문 확인 → 즐겨찾기와 지원 상태 관리. 첫 화면은 공고 검색이며 개인 관리 화면에서는 즐겨찾기 또는 상태가 있는 공고를 확인한다. 관심·지원·면접·결과 상태는 사용자가 정정할 수 있다. 즐겨찾기와 상태는 독립이며 메모, 태그, 개인 마감일은 비공개다. 개인 마감일이 없으면 공고 마감일을 보여준다. 날짜는 한국 기준 달력 날짜로 저장한다.

- 통합 검색은 Greenhouse와 Lever의 공개 채용 피드에서 한국 근무 개발 공고를 읽어 한 목록에 표시한다. 제목·회사·지역·원문 링크를 사용하며, 기술과 경력은 공고 제목에서 확인되는 범위에 한한다. 피드 결과는 서버 메모리에 잠시 캐시한다. 사용자가 외부 공고에 지원 정보를 저장하는 경우에만 기존 URL 등록·지원 관리 경로를 사용한다.
- 직접 등록은 HTTPS/HTTP URL, 제목, 회사명과 선택 입력인 직무, 경력, 지역, 기술, 마감일을 사용한다. 서버는 URL을 요청하지 않는다.
- 키워드는 회사·제목·직무·지역에 부분 일치한다. 직무와 지역은 부분 일치, 경력은 정규화 분류, 기술은 정규화 태그 정확 일치다. 필터는 AND이며 최신 순으로 최대 25개씩 조회한다. 고용24 목록의 기술 스택은 제공되지 않아 제목에서 확인되는 기술만 기록한다.
- 동일 소스의 고용24 인증번호나 동일 소유자의 정규화 URL을 중복 식별한다. 이미 수집된 동일 URL은 기존 공고에 연결한다. 기존 수동 공고와 이후 유입된 같은 URL은 조회에서 하나로 표시하며 기존 추적 정보가 있는 공고를 우선한다. 회사·제목이 같은 다른 URL은 서로 다른 공고일 수 있어 독립 유지한다.

## API와 저장소

Next.js App Router가 UI를 제공하며 NestJS 11이 요청을 검증하고 Supabase Data API를 호출한다. Supabase Auth 세션은 브라우저 메모리에 유지한다. 모든 사용자 API 요청은 Bearer 토큰을 전달하며 NestJS에서 Auth 서버로 확인하고 동일 토큰으로 DB에 접근한다. 응답은 캐시하지 않는다.

| API | 계약 |
| --- | --- |
| GET /health | 런타임 상태 |
| GET /discover | Greenhouse·Lever 공개 공고의 q, role, career, region, skill, page 필터 |
| GET /jobs | 등록·저장 공고의 q, role, career, region, skill, page, saved 필터 |
| POST /jobs | URL과 수동 메타데이터로 등록 또는 기존 공고 반환 |
| PUT /jobs/:id/tracking | 즐겨찾기, 상태, 메모, 태그, 개인 마감일 전체 저장 |
| GET /internal/work24 | 운영 비밀 인증이 필요한 제한된 일일 수집 |

PostgreSQL의 jobs는 인증 사용자용 공식 공고와 소유자 전용 수동 공고를 저장한다. tracking은 사용자와 공고의 복합 PK 및 FK를 사용한다. RLS는 다른 사용자 행 조회·변경 및 참조를 차단한다. 일반 사용자가 공식 출처 행을 쓰지 못하도록 정책과 테이블 권한을 함께 적용한다. ingest_days는 수집 전용이고 일자 PK를 이용해 동시 실행과 동일 일자 재호출을 제한한다. 수집용 비밀 키는 서버에서만 사용한다.

## 공식 API와 무료 운영

- 고용24 [이용 안내](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do)에서 기업회원 가입과 심사·키 발급을 확인했다. [목록 명세](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiSvcInfo.do?fullApiSvcId=000000000000000000000000000000)는 XML, 최대 100건/페이지, 시작 페이지 최대 1000을 명시한다. [상세 명세](https://m.work24.go.kr/cm/e/a/0110/selectOpenApiSvcInfo.do?fullApiSvcId=000000000000000000000000000000%5E000000000000000000000000000001%5E000000000000000000000000000003)는 원문 이동과 공식 출처 이미지 및 안내 문구를 요구한다. MVP는 목록 메타데이터와 원문 이동만 사용한다. 승인된 환경에서 출처 이미지 URL을 설정한다.
- 공개 문서에서 이 프로젝트의 저장 허용 기간과 키별 일일 쿼터를 확인하지 못했다. 승인 범위, 쿼터, 보존 기간, 허용 직종 코드와 출처 자산 확인 전 실호출을 비활성화한다. 자체 초기 한도는 최대 하루 2회(실행당 최대 2페이지, 50건/페이지)이며 승인 한도를 더 낮게 설정할 수 있다. 실패 후 당일 자동 재시도는 없으며 다음 날 재개한다. 원본 XML과 제공처 개인정보는 저장하지 않는다.
- 사람인 별도 승인 후 작업. 다른 사이트는 이용 조건 검토 전 자동 수집하지 않는다.
- [Vercel Hobby](https://vercel.com/docs/plans/hobby)는 개인·비상업적 이용을 지원한다. [NestJS 직접 배포](https://vercel.com/docs/frameworks/backend/nestjs)와 Next.js를 두 프로젝트로 구성한다. [Cron](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing)은 일 1회, 예정 시각부터 최대 59분 오차가 있어 개인 마감 알림과 분리한다. 실수집 승인 전 Cron 설정을 연결하지 않는다.
- [Supabase Free](https://supabase.com/pricing)는 DB 500MB, 기본 egress 5GB, 활성 프로젝트 2개 및 1주 비활동 시 일시 중지를 명시한다. 로컬과 분리된 Preview 환경을 사용하며 공급자 보존 조건에 따른 정리 작업은 운영 적용 전에 검토한다.

## 순서 및 인수 기준

1. Auth와 RLS → 계정 A/B와 익명 요청을 확인한다. B는 A의 수동 공고와 메모를 조회, 변경, 참조할 수 없어야 한다.
2. 직접 등록과 검색 → 정규화 URL 재등록 시 동일 ID, 모든 필터 조합과 한국어 부분 일치, 잘못된 URL·날짜는 400. 저장 후 원문 링크가 열린다.
3. 지원 관리 → 즐겨찾기와 상태를 독립 변경하고 메모, 태그 및 개인 마감일을 다시 로그인한 뒤 확인한다.
4. 고용24 → 합성 XML에서 필드 매핑, 실패 XML, 비활성화, 제한, 재실행 및 출처 표시 검증. 실호출 인수는 승인 후 독립 테스트 환경에서 진행한다.
5. 릴리스 → 빌드, 테스트, 독립 Preview에서 로그인부터 관리까지 확인한 뒤 Production 승인 요청. 운영 파괴적 변경은 별도 승인.
